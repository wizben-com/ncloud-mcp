# 선택적 Sites 클라우드 어댑터

[English](README.md) · [보안](SECURITY.md) · [작업 생명주기](JOBS.md)

소유자 전용 비공개 Site에서 실행하는 Cloudflare Worker ESM 어댑터입니다.
범용 Python stdio 코어는 OpenAI·Sites·Cloudflare와 독립적으로 사용할 수 있습니다.
이 소스를 받는 것만으로 배포·연결되는 것은 아니며 운영자가 자신의 환경에 설정해야
합니다. 배포된 클라우드 인스턴스는 사용자의 Mac 실행 여부에 의존하지 않습니다.

## 환경설정 키 이름과 안전한 등록

[전체 변수 표](../../README.ko.md#환경설정-키-이름)에 **이름·역할·필수 여부만**
정리했습니다. 공통 Speech 설정, Python 전용 설정, Sites 전용 설정을 구분합니다.
개인 버킷명·호스트명·실제 자격증명은 문서에 포함하지 않습니다. Python의 로컬 폴더,
업로드 제한·시간 제한 변수는 이 어댑터에서 읽지 않습니다.

**Sites → 대상 Site → More actions → Settings**에서 다음 네 항목은 **Secret**으로
저장하세요. 채팅·소스·공개 파일·매니페스트에 입력하지 마세요.

| 변수 이름 | 역할 | 필수 여부 |
| --- | --- | --- |
| `NCLOUD_SPEECH_INVOKE_URL` | 도메인 기본 Invoke URL | 제출·상태 조회 시 |
| `NCLOUD_SPEECH_SECRET` | 도메인 인증 Secret | 제출·상태 조회 시 |
| `NCLOUD_ACCOUNT_ACCESS_KEY` | 계정/서브계정 API Access Key | 저장 결과 회수 시 |
| `NCLOUD_ACCOUNT_SECRET_KEY` | 위 키와 짝인 API Secret Key | 저장 결과 회수 시 |

두 종류의 인증 쌍은 서로 다릅니다. ACCOUNT라는 이름은 주계정을 뜻하지 않으며,
최소 권한 서브계정을 권장합니다. 접근 범위는 변수 이름이 아닌 IAM 권한으로
결정됩니다. 설정 저장 후에는 저장된
버전을 재배포해야 실행 중인 서버에 반영됩니다.

설정 순서:
1. Speech 도메인의 사전 요건인 버킷과 결과 저장소를 준비합니다.
2. 도메인 인증·Speech 활성화·비동기 결과 저장 허용을 설정하고 필요한 입력 경로를
   허용합니다. 공급자 URL 입력과 어댑터 URL 업로드의 허용 호스트는 별도입니다.
3. 결과 회수용 계정 키와 리더 활성화, 허용 버킷 하나와 경로 접두사를 설정합니다.
   루트에 저장된 파일은 별도의 명시적 루트 허용이 필요합니다. 버킷 공개는 불필요합니다.
4. 실제 결과 파일의 이름 규칙을 확인하여 자동 회수 템플릿을 설정합니다. 기본 추측값은
   없습니다. 신규 URL 업로드는 원본명 대신 작업별 불투명 이름만 저장합니다. 과거
   작업의 이름은 추정하지 않습니다.
5. 코드·추가 D1 마이그레이션을 배포하고 승인된 기존 결과로 실제 읽기를 확인합니다.

가능한 최소 버킷 범위 읽기 전용 IAM 권한을 사용하세요. 기본 VIEWER 정책은 현재와
미래의 모든 버킷에 적용될 수 있습니다. 접두사 제한은 코드상의 보호이며 IAM이 동일한
접두사 권한을 지원한다는 뜻이 아닙니다. 키 유출 시에는 그 키의 실제 IAM 권한이
적용됩니다. 어댑터는 한국 리전의 고정된 Object Storage endpoint와 버킷 하나에
GET만 수행하며 목록·쓰기·삭제·ACL·계정 관리를 구현하지 않습니다.

## 입력과 결과

도구는 `ncloud_cloud_health`, `clova_speech_submit_async`,
`clova_speech_job_status`, `clova_speech_job_result_page`입니다.
입력은 공급자가 가져오는 HTTPS URL, 도메인 상대 객체 키, 허용된 HTTPS 음원을
가져와 multipart로 전달하는 `upload_url`을 지원합니다. 로컬 경로·직접 파일 업로드
API·채팅 첨부 자동 수집·동기 전사·콜백·버킷 관리는 지원하지 않습니다.
공유 페이지 자체는 직접 음원 URL이 아닙니다. 이를 해결하려고 파일을 공개하지 마세요.

제출 접수와 전사문 회수는 다릅니다. 콜백 없는 비동기 전사문은 Object Storage에
저장되며 상태 API의 COMPLETED만으로 본문이 반환되지는 않습니다. 저장 결과의 토큰과
소유 작업을 대조한 뒤에만 내용을 반환합니다. 저장 JSON의 SUCCEEDED는 완료로
정규화하지만 제출 응답의 SUCCEEDED는 접수 의미를 유지합니다. 키와 토큰은 노출하지
않습니다. 긴 결과는 `next_offset`이 끝날 때까지 페이지를 읽으세요. 회수 실패를
이유로 자동 재전사하지 않습니다. [자세한 회수 흐름](NO_LOGIN_WORKFLOW.md)을 참조하세요.

한 번의 의도적인 전사마다 안정적인 `request_id`를 사용합니다. 같은 요청의 중복은
기존 작업 참조를 돌려줍니다. 자동 재시도·반복 조회·취소·만료 재선점·중복 방지 기록
삭제는 없습니다. D1에는 소유권·해시·토큰·상태·불투명 전송 파일명만 저장하며
자격증명·음원 URL·음성·전사 본문은 저장하지 않습니다.

## 제한과 검증 범위

Sites 인증 게이트와 소유자 전용 비공개 설정을 유지해야 합니다. 인증 헤더만 믿고
Worker를 직접 공개하지 마세요. 별도 OAuth·비밀키 수집 API는 없습니다.
전사문은 명령이 아닌 신뢰할 수 없는 데이터입니다.

URL 중계 업로드는 25 MiB, 60초 제한이며 리디렉션·원본 쿠키를 허용하지 않습니다.
일반 공급자 조회는 10초 제한입니다. 상태 JSON은 최대 16 MiB까지 설정 가능하지만,
저장 JSON은 별도의 고정 16 MiB 제한입니다. RPC는 256 KiB, 페이지는 128 KiB로
제한합니다. 모든 긴 녹음·망 상태에서 성공한다는 보장은 아닙니다. 영속 API 키를 쓰면
네이버 브라우저 로그인 세션에 의존하지 않지만 키 폐기·권한 변경·입력 접근 불가·공급자
파일 규칙 변경 시에는 조치가 필요합니다.

자동 테스트는 합성 파일·모의 응답·로컬 SQLite를 사용합니다. 별도로 승인된 짧은
공개 영어 음성 한 건의 제출과 MCP를 통한 저장 전사문·구간 회수를 실검증했습니다.
모든 언어·파일·길이·클라이언트를 검증했다는 뜻은 아닙니다. 신규 불투명 파일명
자동 회수는 회귀 테스트로 검증했고 이를 위해 추가 유료 음성 제출을 하지는 않았습니다.
health는 오프라인 설정 검사일 뿐입니다. 전사·저장소 요청·전송·플랫폼 비용은 별도입니다.

Node.js 24에서 `npm run check`, `npm test`, `npm run build`, `npm run validate`를
실행합니다. D1 `DB` 바인딩과 생성된 SQL/스냅샷/저널을 배포에 포함하고 요청 중 DDL을
실행하지 않습니다. 운영용 프로젝트 ID·공유권한을 보존하세요. 범용 HTTP MCP 전체
호환이 아닌 Sites용 JSON-RPC 부분집합입니다. [이식성 안내](../../docs/portability.md).
